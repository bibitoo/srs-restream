# 捷兔流媒体服务 · 使用说明

一个装在你自己电脑上的**流媒体服务器**：手机或电脑把画面推上来，它就能
**转推到 B 站/视频号/YouTube 等平台**、**把多路画面合成一路**、**自动录像并回放**。

底层是开源流媒体服务器 SRS，外面加了一层中文控制台，所有操作都在网页上点。

---

## 一、安装后第一次打开

1. 在捷兔桌面点本软件的图标；
2. 首次启动会拉取两个镜像（SRS 约 160MB、ffmpeg 约 300MB），**通常 20~60 秒**，之后每次启动几秒；
3. 等浏览器自动打开控制台，看到顶部「在线源流」「运行中任务」等数字即为就绪。

> 如果 5 分钟后还是打不开，见文末「常见问题 → 首次启动一直打不开」。

控制台默认地址：`http://127.0.0.1:1986/`
在同一个局域网里的手机，用 `http://<电脑的局域网IP>:1986/` 也能打开。

---

## 二、推流：把画面送进来

### 2.1 找到推流地址

打开控制台 → 左侧「直播流」→ 页面顶部有一条 **推流地址**，形如：

```
rtmp://127.0.0.1:1935/live/流名?key=你的访问密钥
```

点「复制」按钮即可。把最后的 `流名` 换成你喜欢的名字，例如 `camera01`。

> **默认访问密钥是 `jetool`**，所以完整地址形如
> `rtmp://127.0.0.1:1935/live/camera01?key=jetool`。
> **`jetool` 只是出厂初值，不是写死的**：在控制台「设置」里改过、或由捷兔桌面下发过新密钥后，
> 旧密钥立即失效，推流地址和浏览器访问都要换成新密钥（控制台打开时会弹框让你输入）。
> 新密钥会存进安装目录的 `data/config.json`，重启后仍然是它，不会退回 `jetool`。

### 2.2 用 OBS 推流

- 设置 → 直播 → 服务：**自定义**
- 服务器：`rtmp://127.0.0.1:1935/live`
- 串流密钥：`camera01?key=jetool`（把 `jetool` 换成你当前的访问密钥）
- 编码：**H.264**（不要选 H.265/HEVC，浏览器预览播不了）
- 点「开始直播」

### 2.3 用手机 App 推流

手机和电脑连同一个 Wi-Fi，推流地址里的 `127.0.0.1` 换成电脑的局域网 IP，
例如 `rtmp://192.168.1.10:1935/live/phone`。

### 2.4 用「捷兔行迹」App 推流（自动发现）

同一 Wi-Fi 下，行迹 App 的「设置 → 推流与视频规格 → RTMP 地址」会自动列出本服务：

```
📡 捷兔流媒体服务 · 192.168.1.10     ← 点一下就用这个地址
✅ rtmp://192.168.1.10:1935/live/stream   ← 推流成功过的地址，也在这里
```

点开候选项即填入，**也可以手动改成任何地址**（推到别的服务或第三方平台都行）。
地址里的 IP 和端口会被替换成本机的，流名保留你原来填的。

### 2.5 用命令行测试

```bash
ffmpeg -re -f lavfi -i testsrc2=size=1280x720:rate=25 \
       -c:v libx264 -preset veryfast -g 50 \
       -f flv rtmp://127.0.0.1:1935/live/test
```

推上去之后，「直播流」页会立刻出现一行，状态是「推流中」。

## 三、直播流页：看、录、转

每一行是一个正在推的流：

| 按钮 | 作用 |
| --- | --- |
| **预览** | 在当前页弹窗里直接看画面（弹窗里就是播放器，另附「复制 FLV/HLS 地址」，可用 VLC 播） |
| **开始录制 / 停止录制** | 手动控制录像。**默认开启自动录制，推流一上线就在录了**，此时按钮显示「停止录制」 |
| **转推** | 用这一路流新建一条转推任务 |

「录制」列会显示 `录制中 00:01:23`，实时更新。页面顶部还有「自动录制：开/关」标识。

## 四、转推到第三方平台

### 4.1 先登记平台地址

「推流目标」→「新增地址」，填入平台给你的 RTMP 推流地址，例如：

```
rtmp://live-push.bilivideo.com/live-bvc/xxxxx?key=yyyyy
```

> ⚠️ **如果目标在宿主机上的另一个服务**（比如你电脑上还跑着别的 SRS/nginx-rtmp），
> **不要写 `127.0.0.1`** —— 在容器里它指向容器自己。请写电脑的局域网 IP，
> 或 `host.docker.internal`。

### 4.2 再建转推任务

「转推任务」→「新建任务」：

- **单流转推**：一个源 → 一个或多个平台。走 `-c copy` 直转，**不转码、几乎不占 CPU**。
- **混流转推**：多个源合成一路 → 再推到平台。只编码一次，多个平台共用（每个平台一个轻量中继）。

混流布局：

| 布局 | 效果 | 适合 |
| --- | --- | --- |
| 单画面 | 只用第一路铺满 | 只想统一分辨率 |
| 上下分屏 | 多路竖向等分 | 主持人 + 画面 |
| 左右分屏 | 多路横向等分 | 双人访谈 |
| 宫格 | 2×2 / 3×3 自动排布 | 多机位监控 |
| 画中画 | 主画面 + 角落小窗 | 讲解类 |
| 圆窗口 | 主画面 + 圆形小窗 | 主播头像/特写 |

其它可调项：输出分辨率（含竖屏 1080×1920）、帧率、视频/音频码率、音频混音方式、
小窗尺寸与位置、宫格间距、填充底色。

勾选「源流一上线就自动开始推流」后，不用手动点启动。

### 4.3 看状态

任务卡片上每个平台单独显示状态：`运行中 / 重连中 / 已停止`，并给出**重连次数和具体错误**。
点「日志」能看到完整的 ffmpeg 命令与输出。

## 五、录像与回放

推流上线会自动录（可在设置里关），也可以手动录。

「录像库」里：

| 操作 | 说明 |
| --- | --- |
| 卡片内播放器 | 直接播、可拖进度条 |
| **下载** | 下载 MP4 原文件 |
| **手机播放** | 生成 HLS 切片再用播放器播，**手机/微信内置浏览器播不动时用这个** |
| **修复** | 文件没正常收尾（如强杀进程）时重建索引，几秒完成 |
| **删除** | 删除视频文件（HLS 切片一起删） |

**录制中**的卡片不提供播放器，只显示「正在录制 · 已录 N 分钟 · 大小」，停止后自动封装成可播放 MP4。

默认每 30 分钟自动分段（避免单个文件过大），可在设置里改成 0 关闭分段。

## 六、让 AI 帮你操作（MCP）

本软件内置 MCP 服务，Cursor / Claude Desktop / Cline 这类 AI 客户端可以直接问它：

- 「现在有哪些直播流？」→ 调 `streams_list`
- 「把 camera01 推到 B 站」→ 调 `job_create` + `job_start`
- 「刚才那段录下来了吗？」→ 调 `recordings_list`
- 「两路做成圆窗口推到 B 站」→ 调 `mix_and_push` 一步到位
- 「现在什么情况？」→ 调 `stream_overview` 一次看全

配置方式（Cursor → 设置 → MCP）：把地址填 `http://<本机IP>:1986/mcp`，
认证头写 `Authorization: Bearer 你的访问密钥`。

如果你装了捷兔桌面，正常情况下**不用配**——装好本软件后，桌面会自动把 10 个工具
提供给 AI 客户端（形如 `jetsream__streams_list`）。

写操作（创建任务、启停、录制）建议让 AI 先跟你确认再执行。

## 七、设置

| 设置项 | 说明 |
| --- | --- |
| 有流推上来就自动录制 | 默认开。关掉后只能手动录 |
| 录像分段时长 | 分钟，0 = 不分段，默认 30 |
| 对外访问地址 | 生成播放链接用，留空按当前访问地址推断（推荐留空） |
| 对外推流地址 | 给用户看的推流地址，如 `rtmp://192.168.1.10:1935/`。留空则用默认端口 |
| SRS API 地址 / 播放服务地址 | 容器内部地址，正常不用改（`http://srs:1985`、`http://srs:8080`） |

## 八、数据与磁盘

所有数据在**软件安装目录的 `data/`** 下：

```
data/
├── config.json      推流目标、任务、设置
├── recordings/      录像 MP4（和同名 .json 元数据）
├── hls/             录像的 HLS 切片（点「手机播放」才生成）
└── logs/            任务日志、访问日志
```

- 备份：拷走整个 `data/` 即可
- 清理：删 `recordings/` 里的文件（或在界面上删，会同步清理）
- 估体积：1080p 约 **每 10 分钟 450MB**

## 九、改端口 / 端口被占用

默认用 1935（推流）和 1986（控制台）。

**正常情况下不用管**：如果这两个端口被别的程序占用，捷兔桌面会自动换一个空闲端口，
并把新端口告诉本服务；控制台和推流地址都会自动跟着变，**以控制台页面上显示的地址为准**。

如果你是自己用 `docker compose` 启动（不经过捷兔桌面），端口改了要同时告诉服务：

1. 打开软件安装目录（`workDir` 是 `jetstream`）；
2. 在 `docker-compose.yml` 同级新建 `.env`：

```ini
SRS_RTMP_PORT=19350
UI_PORT=19860
```

3. 重新启动；控制台地址变成 `http://127.0.0.1:19860/`，推流地址会自动变成 `19350`。

> 端口是「宿主机端口」，容器内部始终是 1935 / 1986。看不到「推流端口是多少」时，
> 打开控制台「设置 → 诊断」，`endpoints` 里的 `hostPort` 就是当前实际使用的推流端口。

## 十、常见问题

**首次启动一直打不开**
首次要拉两个镜像（共约 460MB，20~60 秒），这期间浏览器可能显示拒绝连接。可以在安装目录里执行
`docker compose logs -f`，看到 `SRS 已就绪` 和 `控制台已启动` 就好了。若报拉取失败，
说明 Docker 访问不了镜像仓库，检查网络或配置镜像加速。

**打不开控制台 / 一直提示要密钥**

控制台受访问密钥保护，默认 `jetool`（只是初值）。如果在控制台设置页或由捷兔桌面改过，
请用**新**密钥；旧密钥会立即失效。忘记时可到安装目录看 `data/config.json` 里的 `access_key`。

**推流被拒绝（ffmpeg 报 Input/output error）**

推流地址漏了 `?key=你的访问密钥`。补上即可。

**推流了但「直播流」里没有**
1. 推流地址的端口要和页面顶部显示的一致（端口被占用时会被自动改号，例如从 1935 变成 1936，
   照旧端口推就会推到**别的程序**上，本服务自然看不到流）；
2. OBS 里「服务器」和「串流密钥」要分别填对：服务器到 `.../live`，密钥是流名；
3. 用 `docker compose logs srs` 看有没有推流连接记录。

**预览是黑屏**
- 该流是否「推流中」；
- OBS 编码是不是 **H.264**（H.265 浏览器播不了，弹窗会提示）；
- 看弹窗里那行状态：`已连接：video/x-flv …` 说明流已经进来了（黑屏是源本身没画面）；
  写「8 秒还没收到画面」多半是流名/端口不对或密钥不对；
- 还看不出来就点弹窗里的「新窗口打开」，看 SRS 播放器页的具体报错。

> 预览是控制台弹窗里的原生播放器（mpegts.js 播 HTTP-FLV），播放库随程序内置，
> 不需要联网。以前是把 SRS 自带的播放器页套进弹窗，那个页面自带上导航条和一堆文字，
> 一旦没播起来就只剩"一堆 HTML 内容"，现在不会了。

**录像只能播一点点 / 拖不动**
文件可能没正常收尾，点卡片上的「修复」重新封装；正在录制中的文件本来就不能拖。

**转推一直「重连中」**
看卡片上的红色错误：
- `Connection refused`：目标地址/端口不对，或平台没开；
- `127.0.0.1 在容器内指向容器自己`：把目标改成电脑的局域网 IP，或 `host.docker.internal`；
- 平台侧报鉴权错误：检查推流密钥是否过期。

**混流任务很吃 CPU**
`mix` 模式每路任务只编码一次（veryfast + zerolatency）。720p@25 双路约 1~1.5 核；
4 路以上建议降到 720p 或减少路数。纯转推（单流转推）几乎不占 CPU。

**换了台电脑 / 重装**
`data/` 目录拷过去即可，任务和目标都在 `config.json` 里。

## 十一、它由什么组成

安装后是两个容器（都用公开镜像，**不需要本地编译**），控制台已经帮你串好了，了解即可：

| 容器 | 作用 | 端口 |
| --- | --- | --- |
| `jetstream-srs` | SRS 流媒体引擎：接收推流、输出 HTTP-FLV/HLS | 1935 / 8080 / 1985 |
| `jetstream-control` | 控制台与业务 API：转推、混流、录制、回放 | 1986 |

预览和播放都走控制台的 1986 端口（内部反向代理到 SRS），所以只要 1986 能打开，
画面就能看。数据卷挂在安装目录的 `data/`，容器重建不会丢。
